# PCブラウザでのSolflare Devnet検証

この手順はChrome等のPCブラウザとSolflare拡張機能で行います。独自Anchorプログラムのデプロイは不要です。NFT操作は既存のDevnet Metaplex Coreプログラムを使います。

## 1. アプリを起動

Node.js 22以上、Git、PCのSolflare拡張機能を用意します。

初めて取得する場合:

```sh
git clone --branch codex/nftlab-sim-mvp https://github.com/haruharuoharu/nftlab-sim.git
cd nftlab-sim
npm ci
npm run dev
```

既に取得済みの場合（ローカル編集がある場合は先に保存）:

```sh
cd nftlab-sim
git switch codex/nftlab-sim-mvp
git pull --ff-only
npm ci
npm run dev
```

PCで `http://localhost:3000` を開きます。ターミナルは起動したままにします。PostgreSQLやAnchorの設定は不要です。

## 2. Solflareを接続

1. SolflareのネットワークがDevnetであることを確認します。
2. アプリの「Devnetで体験」を押します。
3. 右上のウォレット接続ボタンからSolflareを選び、Solflareで接続を承認します。
4. アプリに表示される公開アドレスがSolflareの口座Aと一致することを確認します。
5. 0.05テストSOL未満なら0.5テストSOLの自動取得を試みます。「準備完了」を確認します。配布制限などで取得できない場合は公開アドレスをコピーして画面のFaucetを開き、Devnetで取得後に「残高を再確認」を押します。再要求は10分間隔です。この目安は独自Anchorのデプロイ費用を含みません。

アプリを起動する前に、以下で接続先と残高を読み取り確認することもできます。

```sh
npm run check:devnet -- --wallet YOUR_DEVNET_PUBLIC_ADDRESS
```

Anchor・公開メタデータを指定していない場合、その項目は `pending` です。これはlocalhostでの手動Core検証を妨げません。公開アドレスだけでは署名できないため、実取引の承認はSolflareで行います。

再読み込み後はウォレットに自動再接続しません。右上の「Solflareを接続」（未選択時は「ウォレットを選択」）から接続し直します。接続後はボタンにウォレット名と短縮アドレス、画面に公開アドレスと残高が表示されます。学習進捗・発行済み修了証は接続状態とは別に保存されています。

接続手順の参考: [Solflare公式のデスクトップdApp接続ガイド](https://help.solflare.com/en/articles/5797210-how-to-connect-to-dapps-using-the-solflare-wallet-desktop)。Solflareが一覧に見えない場合は、拡張機能を有効にし、ロックを解除してアプリのページを開き直します。

## 3. 最初はチケット1件で確認

最初は口座Aだけで進められる「練習相手（ウォレット1つ）」を使います。

| 操作 | アプリで行うこと | 確認する結果 |
|---|---|---|
| クイズ | チケットの2問に回答 | NFT発行ボタンが表示される |
| 発行 | Aで「NFTを発行する」を押し、Solflareで承認 | NFTアドレスとAの所有者表示。Explorerで成功 |
| 譲渡 | 「NFTを譲渡して受け取る」をAで承認 | 同じ取引で練習相手へ譲渡・Aへ返送。所有者表示はA。Explorerには2つのCore転送命令 |
| 利用 | Aのまま「NFTを利用・消費する」を押し、Solflareで承認 | 「体験完了」。ロイヤルティ特典が解放される |

別口座への譲渡を試す場合は「別のウォレットへ送る」を選び、Bの公開アドレスを入力します。Bには利用の手数料用テストSOLが必要です。送信後はAを切断してBを接続し、Bで利用します。Aのまま利用しようとすると所有者の違いで拒否されます。NFTを消費するまで、他のアプリから同じNFTを操作せずに検証してください。

## 4. 中断後の復旧

承認後に確認が中断した場合、ページを開き直し「Devnetで体験」を選びます。

- 「確認待ちの取引があります」が表示されたら「取引状況を再確認」を押します。再確認のためのウォレット署名は不要です。
- 成功が確認されると、保存済みの同じ署名・NFTアドレスから学習進捗が復旧します。
- 確定した失敗が確認されると、進捗を進めずに確認待ち記録を解除します。
- 履歴が取得できない場合は、期限が過ぎていても記録を保持します。新規発行や進捗リセットは停止したままです。Explorerや履歴対応RPCで確認します。
- 複数タブでの取引は順番に行います。別タブが処理中の場合、新しい署名依頼は開始しません。

復旧が終わるまで、ブラウザのサイトデータやlocalStorageを削除しないでください。記録は同じPC・ブラウザ・originに保存されます。ブラウザの全データ削除や別端末では復旧できません。

## 5. 残りのシナリオと修了証

チケットが通ったら、ロイヤルティ特典とメンバーシップも同じ手順で確認します。練習相手への往復譲渡なら、全操作をAのまま進められます。全3件完了後に修了証を発行します。

localhostで発行したNFTは、メタデータのURLもlocalhostになります。外部ウォレットでの画像・説明表示を検証するには、公開アプリのHTTPS URLを `NEXT_PUBLIC_APP_URL` に設定した環境で新規発行する必要があります。このローカル検証ではNFTアドレス・所有者・取引結果を中心に確認します。

## 6. 任意のAnchor学習記録を追加

Coreの3シナリオと修了証を発行済みでも、学習をリセットせずに追加できます。独自プログラムはDevnetへデプロイ済みのため、Anchorの再ビルド・再デプロイは不要です。

1. `.env.local` の `NEXT_PUBLIC_ANCHOR_PROGRAM_ID` を `BUdXZQwEUkSkQve9wmdzGG4kkz8ViGmvnJ1b2EDAviwR` に設定します。他の設定は保持します。
2. Next.jsを再起動します。本番起動の場合は再ビルドも行います。同じブラウザで `http://localhost:3000` を開き、「Devnetで体験」を選びます。
3. 3/3完了と既存の修了証が残っていることを確認し、記録するウォレットを接続します。記録は接続ウォレットの自己申告であり、修了証NFTの所有権とは別です。
4. 修了証の下にある「学習完了を記録」を押し、Solflareで1回の取引署名を承認します。3件の学習記録を1つの取引で送信します。テストSOLから記録アカウントのrentと手数料を支払います。
5. 「接続ウォレットに学習完了を記録しました」、記録した公開アドレス、Explorerリンクを確認します。既存の修了証NFTを再発行することはありません。
6. 再読み込み・再接続後も記録と修了証が表示され、同じウォレットのボタンが「このウォレットに記録済み」になることを確認します。確認が中断した場合は、既存の「取引状況を再確認」で復旧します。

新規の修了証発行では、Anchorを有効にすると学習記録の後にCore NFT発行の署名を依頼します。先に学習記録を追加済みなら、その記録を再送信せずに修了証を発行します。別のウォレットへ切り替える場合は表示アドレスを確認してください。ブラウザには直近の学習記録を保存し、それ以前の記録もDevnet上には残ります。

## 結果として記録するもの

- 検証したブラウザとSolflareのバージョン。
- 発行・譲渡・消費のExplorerリンク、または公開取引署名。
- 各操作後の画面メッセージ。失敗した場合は、その操作と表示された文面。
- 全シナリオ完了後の修了証NFTアドレス。

ブラウザ拡張ウォレットでの実取引と承認はユーザー自身が行います。自動テストの成功と実機確認の結果は分けて記録します。
